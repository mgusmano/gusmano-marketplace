# Ext JS Upgrade Expert

## Core Rules
* At the start of every task, output a mcp__ccd_turn__update_plan or structured status box or checklist using markdown code blocks so the progress is explicitly visible in the terminal. If available, use ToDos or todowrite or todowrite or mcp__ccd_turn__update_plan Model Context Protocol tool to document progress.  For mcp__ccd_turn__update_plan you must always provide a scope parameter.
* **Constraint**: Leave unrelated code untouched
* **Thinking**: Be terse when creating and outputting thinking/thought tokens
* **Model Context Protocol Tools**: Always call Model Context Protocol Tools directly via Model Context Protocol, never via Bash or Terminal. 
* **Continue**: Continue through the entire skill without asking.
* **Constraint**: Use ToDos or todowrite Model Context Protocol tool to document progress
* **Path Definition**:
  * `<rootPath>` = the full root path of the project / the current working directory
  * `<sourceRoot>` = Folder containing the application to be upgraded
  * `<targetRoot>` = Folder containing the newly created v8 application
  * `<targetSDK>` = Folder containing the ExtJS Version 8 SDK files
  * `<projectType>` = Project type: `senchaCmd`, `extGen`, `custom`, `architect`

## Workflow Instructions

1. **Determine There Is Exactly One Target Folder**
   * List the top-level folders in `<rootPath>`, **excluding hidden folders** (names beginning with a dot, e.g. `.sencha`, `.git`, `.vscode`).
   * **Precondition:** this skill interrogates **one and only one** project folder. 
   * If there are zero folders, do not proceed — stop the entire skill immediately and report the outcome (no project folder / ambiguous — multiple candidates found).
   * **if there is more than 1 folder**, then askAQuestion listing all folders and set the answer to `<sourceRoot>`
   * **Otherwise, if exactly one folder exists**, the exactly one folder is set to `<sourceRoot>`

2. **Detect Which Project Type (`<projectType>`)**
    * Run Model Context Protocol tool `extjs-project-type`
        - folderPath=`<sourceRoot>`    
        returning: 
        - `<projectType>`
        - `<toolkit>`
        - `<theme>`
        - `<sourceVersionShort>`

3. **Branching Execution**


#### If `<projectType>` = `senchaCmd` (is a Sencha Cmd application)
* Only run this branch 1 time.
    * MUST be run as a shell command: `extjs-tools_extjs-initilize-with-sencha-cmd`, with exactly these 2 parameters, always include progress=true
        - progress=true
        - rootPath = `<rootPath>` the full root path of the project - NOT `<sourceRoot>`
        returning:
        - `<sourceRoot>` 
        - `<sourceApps>`
        - `<sourcePackages>`
        - `<targetRoot>`
        - `<targetV8Root>`
        - `<lintFilesStrings>`
    * if a result=fail is returned , then end processing - do not do any exploring, ALWAYS END THIS SKILL — echo the tool's fail reason
    * if result=success is returned, continue.
* display the list of `<lintFilesStrings>`
* Make all Lint fixes
    * If a file says it is generated by Sencha Cmd and should NOT be edited - then do not edit the file
    * For each `<lintFilesStrings>` read the file and find each //**LINT START** to //**LINT END** only find where `//AI:` with no text to the right - make the changes needed.  if `// additional:` exists prioritize that
    * Read each file from `<lintFilesStrings>` one at a time and fully make changes to that file before moving to the next file
    * If there are no file names in `<lintFilesStrings>` with //**LINT START** to //**LINT END** then continue.

    * For any duplicate functions and stubs, keep the live implementation, comment out the stub, and rename the other copy 
    * fix any unparseable unreferenced files

    * one of the comments is `// AI:` - use that to write any comments to the right of it on what was done to fix the linting issues.  Do not exceed the 1 line comment limit.  If there are multiple // AI: comments, combine them into one comment.
    * do not remove the resolved lint comments, leave them in the code for future reference.
* Production Build & Validation
    * Run Model Context Protocol tool `extjs-tools_sencha-stop` and wait for it to fully complete.
    * Do the following steps for each `<appFolder>` in `<sourceApps>` 
      a. Run Model Context Protocol tool `extjs-tools_sencha-app-build`
        - progress=true
        - cwd=`<appFolder>`
      b. Inspect `<targetRoot>/ext/build/ext-all-rtl-debug.js` to debug and resolve any compilation errors
      c. When an error is resolved put a comment `//**UPGRADE FROM MODEL START**` above the resolution and put a comment `//**UPGRADE FROM MODEL END**` below the resolution
    * If an error is resolved, repeat starting at step 1. Start Server until all errrors are resolved.
* Dev Server & Smoke Test Validation
    * Do the following steps for each `<appFolder>` in `<sourceApps>` 
      * assign `<currentAppPath>` to `<appPath>` in `<sourceApps>` 
      a. Run Model Context Protocol tool `extjs-tools_sencha-stop` and wait for it to fully complete.
      b. Run Model Context Protocol tool `extjs-tools_sencha-app-watch`
        - progress=true
        - cwd=`<appFolder>`
        and wait for the server ready signal.
      c. Run Model Context Protocol tool `extjs-tools_extjs-capture-logs-puppeteer`
        - progress=true
        - appPath=`<currentAppPath>`
        * to produce basic smoke test to find runtime errors. 
        * Never run puppeteer on its own - only use this Model Context Protocol tool.
        * if `extjs-tools_extjs-capture-logs-puppeteer`was successful, Run Model Context Protocol tool `extjs-tools_sencha-stop` and wait for it to fully complete.
        * Resolve any errors from `extjs-tools_extjs-capture-logs-puppeteer` and rerun from the beginning of Smoke Test until no more errors
        c. When an error is resolved put a comment `//**UPGRADE FROM SMOKE TEST START**` above the resolution and put a comment `//**UPGRADE FROM SMOKE TEST END**` below the resolution 
      e. Reseach and fix runtime errors from capture logs, do not research warnings.  Inspect `<targetRoot>/ext/build/ext-all-rtl-debug.js` to resolve any runtime errors
      f. If an error is resolved, repeat starting at step 1a. Continue until all errors for `<appFolder>` are resolved.
      g. When an error is resolved put a comment `//**UPGRADE FROM EXT SDK START**` above the resolution and put a comment `//**UPGRADE FROM EXT SDK END**` below the resolution 
        * Do not move to the next `<appFolder>` until all errors are resolved.
* for all 404 errors - Failed to load resource: the server responded with a status of 404 (Not Found)
    * if the 404 is for favicon.ico then skip it, do not create any backend server
    * create backend servers for each needed port / 404 error using nodejs and include all backend ports as dummy/test ports so that the frontend can be tested - use the ports the frontend code uses. 
    * deliver each backend server as a separate nodejs process and run them in the background so that the frontend can be tested.
    * create trhe backend servers in `<targetRoot>/extjs-upgrade-backend-servers` and include a README.md file with instructions on how to run the backend servers.
* Cleanup and Documention Summary
    * Only start this step if all runtime errors are resolved.
    * Show each `<appFolder>` in `<sourceApps>` in an inline browser at `http://localhost:1977/<currentAppPath>`
    * Keep `http://localhost:1977/<currentAppPath>` running - do not stop
    * Create `<targetRoot>/UPGRADE.md` documenting:
        -steps
        -changes
        -`Override of Class` notes
        -Model Contect Protocol tool `extjs-tools_extjs-capture-logs-puppeteer` notes
        -residual warnings
    * Output the final path to `<targetRoot>/UPGRADE.md`.
    * Do not outout any text summary, explain that the upgrate is now complete and that the summary is available in  `<name>/UPGRADE.md`  
* Output Format
    * Return the final analysis in the following structured format:
      * **Source Project Type (`<projectType>`):** `senchaCmd` | `extGen` | `custom`
      * **Source Folder (`<sourceRoot>`):** `<path_to_sourceRoot>`
      * **Target Folder (`<targetRoot>`):** `<path_to_targetRoot>`
      * **Source Ext JS Version (`<sourceVersionShort>`):** `<sourceVersionShort_string>`
      * **Source Ext JS Toolkit (`<toolkit>`):** `classic` | `modern` | `unknown`
      * **Source Ext JS Theme (`<theme>`):** `<theme_name>`
      * **Lint Folders Processed (`<foldersProcessed>`):** `<foldersProcessed>`
      * **Lint Files Fixed (`<filesFixed>`):** `<filesFixed>`
      * **Lint Folders Failed (`<foldersFailed>`):** `<foldersFailed>`
#### End If `<projectType>` = `senchaCmd` (is a Sencha Cmd application)
